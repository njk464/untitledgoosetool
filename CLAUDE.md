## Project Overview

**Untitled Goose Tool** (Goosey) is a CISA-published hunt and incident response tool for collecting telemetry from Microsoft cloud environments: Entra ID, Azure, M365, Microsoft Defender for Endpoint (MDE), and Defender for IoT (D4IoT). It is designed for forensic data export after incidents.

## Installation and Setup

```sh
# Create and activate a virtual environment (recommended)
python3 -m venv .venv
source .venv/bin/activate  # Linux/Mac
# .venv\Scripts\activate   # Windows

# Install the package
pip install .
```

Requires Python 3.9–3.13 (enforced by setup.py). Python 3.12+ is recommended for better logging (taskName in log format).

## CLI Commands

The `goosey` entry point (defined in `setup.py`) exposes these commands via the `fire` library:

```sh
goosey setup         # Create/delete Azure app registration and service principal
goosey conf          # Generate .conf and .auth configuration files interactively
goosey honk          # Authenticate + run data collection (auth is automatic)
goosey autohonk      # Alias for honk (backwards compatibility)
goosey d4iot         # Authenticate for Defender for IoT separately
goosey web           # Launch browser-based UI
goosey --version     # Display version
```

## Architecture

### Execution Flow

`goosey honk` is the primary data collection command:
1. Loads auth tokens (from `.auth` file generated by `goosey auth`)
2. Parses `.conf` configuration file (INI format)
3. Instantiates datadumper objects for each enabled platform
4. Creates async tasks via `asyncio.create_task()` for each enabled data pull function
5. Executes all tasks concurrently with `asyncio.gather()`

### Module Responsibilities

- **`main.py`** — Entry point; maps CLI subcommands to functions via `fire.Fire()`
- **`honk.py`** — Main orchestrator; assembles and runs async task lists across all platforms
- **`auth.py`** — MSAL OAuth flows, token acquisition and refresh, `.auth` file management
- **`conf.py`** — Interactive `.conf` file generation and management
- **`datadumper.py`** — Abstract base class for all dumpers; `data_dump()` resolves `dump_<key>` methods by name and wraps them as async tasks; `func_wrapper` handles per-task error isolation
- **`m365_datadumper.py`** — M365/Exchange Online: UAL (Unified Audit Log), mailboxes, inbox rules, mobile devices
- **`entra_id_datadumper.py`** — Entra ID/Azure AD: sign-in logs, audit logs, risk detections, conditional access policies
- **`azure_dumper.py`** — Azure resources: VMs, networking, storage, Security Center, Log Analytics workspaces
- **`mde_datadumper.py`** — Microsoft Defender for Endpoint: alerts, incidents, advanced hunting queries, machines
- **`d4iot_dumper.py`** — Defender for IoT: sensors, alerts, vulnerabilities, PCAPs
- **`utils.py`** — Shared utilities: colored logging setup, config parsing, API helpers, file I/O, encryption, date handling
- **`csv.py`** — Post-processing to replace GUIDs in output JSON/JSONL files with human-readable text

### Adding a New Data Collection Method

1. Add a `dump_<methodname>` async method to the appropriate `*DataDumper` class
2. Add `<methodname>` as a key in the `calls` dict passed to `data_dump()` in `honk.py`
3. The base class `DataDumper.data_dump()` will automatically discover and schedule it as an async task

### Key Patterns

- All data collection methods are `async` and use `aiohttp.ClientSession` (stored as `self.ahsession`)
- Output is written as JSON/JSONL files to `self.output_dir`; reports to `self.reports_dir`
- Rate limiting: 429 responses are handled with exponential backoff in `utils.py`
- Config file encryption: `.auth` and `.conf` files can be AES-encrypted via `pyAesCrypt`
- Government cloud support: GCC and GCC High endpoints are configurable
- Save state for UAL: incremental collection resumes from last checkpoint

### Authentication Architecture

Auth tokens are stored in a `.auth` JSON file keyed by API endpoint type:
- `app_auth.graph_api` — Microsoft Graph
- `app_auth.outlook_office_api` — Exchange/O365
- `app_auth.resource_manager` — Azure Resource Manager
- `app_auth.securitycenter_api` — Microsoft Security Center
- `app_auth.log_analytics_api` — Log Analytics

Each datadumper receives only the token(s) it needs at instantiation time in `honk.py`.
